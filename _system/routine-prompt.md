# ChatGPT scheduled news research: project-week workflow

Repository: KarterGIT/newsletter-vault, branch main.
Cadence: Monday, Wednesday, Friday at 5 PM Eastern.
Project Week 1 starts Monday 2026-10-05 and each project week is seven days. For example, October 13, 2026 is **Week 2**. Do not use ISO week numbers W41/W42 for titles, folders or links.

1. Read this file, `_system/sources.md`, `_system/pull-template.md`, the root `Newsletter Template.md`, the current `Week N/Week N.md` overview, all current source files in `Week N/Sources/` and the most recent existing draft if any.
2. Search broad current AI news within the last 3–4 days or since the previous successful research pull, using reputable primary announcements, original studies and established journalism. Open actual URLs, verify article dates and facts, compare against earlier notes, and select up to 20 important unique stories. Attribute model-developer claims as claims. Exclude Reddit, social rumors, unsupported search snippets, inaccessible unverified claims, aggregators and AI news farms.
3. If no credible new stories can be checked, **do not create an empty news file**. Report the failed run and its blockers. Do not add unverified stories to reach a quota.
4. Otherwise create precisely one dated Markdown source note, `Week N/Sources/YYYY-MM-DD-day.md`, using the current pull template. It must include exactly one internal `[Week N overview](../Week%20N.md)` link and real external original article links. Use standard relative Markdown links with spaces encoded as `%20`; do not use editor-specific wikilinks. Do not link directly to other day's notes or operational templates.
5. After committing and verifying the new source file, update ONLY the section between `<!-- WEEK FILES START -->` and `<!-- WEEK FILES END -->` of `Week N/Week N.md` to list existing daily pulls and a draft if available; preserve the template link and human notes outside the section. Each week hub links to `[Newsletter Template](../Newsletter%20Template.md)`.
6. If it is the first run of a new project week, create `Week N/Week N.md` with the single `[Newsletter Template](../Newsletter%20Template.md)` link, the dated source-note list and a draft section pending Sunday; then add a link for the week inside the `<!-- WEEKS START -->` and `<!-- WEEKS END -->` markers in `Newsletter Template.md`. Keep each week to up to THREE intended research collection days, Monday, Wednesday and Friday. Avoid duplication when an earlier manual test substituted for a failed collection.
7. Do not overwrite existing daily notes, historical source files, or a draft. Confirm every created/updated GitHub file by reading it back. If an unattended authorization or web request fails, report the error and provide the Markdown when available instead of assuming it was saved.
